# EP Island MVP

Прототип автоматизированной системы управления процессом «Остров Дураков» по требованиям документов Vision, SRS, Use Case и SDP.

## Реализованные сценарии

- UC-01: поиск в имитаторе реестра, регистрация должника, создание направления, безопасное повторение по `Idempotency-Key`, передача конвою и удаление ошибочного направления.
- UC-02: поиск направления по числовому номеру, автоматическое заполнение данных, проверка дублей и присвоение 10-символьного ID.
- UC-03: отображение загрузки зон, рекомендация по формуле 0,5/0,3/0,2, ручной выбор зоны и ручная фиксация процента трансформации оператором. История изменений сохраняется; при 100% система автоматически создаёт задание на стрижку.
- UC-04: инженер вручную фиксирует массу шерсти и фактическую энергию за смену. Прогноз энергии рассчитывается автоматически, а фактические данные без дополнительных действий передаются в бухгалтерию. При сбое фоновое задание повторяет передачу.
- UC-05: дашборд, отчёт с фильтрами и экспорт CSV в UTF-8 с разделителем `;`.
- Демонстрационный ролевой доступ и журнал аудита изменений.

## Стек

- Java 21, Spring Boot 4.1.1;
- PostgreSQL 16+;
- React 19 и Vite 8;
- единый исполняемый JAR для FreeBSD-хоста.

## Структура приложения

- `api` — тонкие HTTP-контроллеры: приём запроса, валидация, проверка роли и вызов сервиса; SQL и бизнес-правил в контроллерах нет;
- `referral`, `resident`, `zone`, `energy`, `analytics` — независимые feature-модули. В каждом доменные модели и enum, сервис бизнес-правил и JDBC-репозиторий;
- `energy.AccountingGateway` — граница интеграции с бухгалтерией; в прототипе подключён управляемый имитатор;
- `auth` — демонстрационная сессия и проверка ролей;
- `service` — типизированный аудит с enum действий и сущностей;
- `frontend/src` — React-компоненты, API-клиент и независимые экраны направлений, регистрации, зон, энергии и отчётов;
- `src/main/resources/static/react` — production-сборка React, которая включается в единый исполняемый JAR.

Интерфейс использует тёмную операционную тему из согласованных примеров Use Case: компактная верхняя навигация, фиолетовый акцент и единая цветовая индикация статусов.

## Локальный запуск в Docker

Для демонстрации не нужны Java, Maven или внешняя PostgreSQL:

```bash
cp .env.example .env
./scripts/local-up.sh
```

Интерфейс: `http://127.0.0.1:25074`. PostgreSQL доступна на `127.0.0.1:54329`. Порты и учётные данные можно изменить в `.env`.

Скрипт сам выбирает доступный вариант Compose и запускает контейнеры в фоне. Состояние и логи:

```bash
docker-compose ps
docker-compose logs -f application
```

Остановка с сохранением базы:

```bash
./scripts/local-down.sh
```

Полный сброс локальных данных: `docker-compose down -v`.

## Разработка frontend

Для режима Vite с HMR сначала запустите backend через Docker, затем:

```bash
cd frontend
pnpm install
pnpm dev
```

React-интерфейс будет доступен на `http://127.0.0.1:5173`, а запросы `/api` проксируются в Spring Boot. Production-сборка: `pnpm build`.

## Локальный запуск без Docker

```bash
export SPRING_PROFILES_ACTIVE=local
mvn spring-boot:run
```

Профиль `local` ожидает PostgreSQL на порту `54329`. По умолчанию приложение слушает порт `25074`. Проверка: `GET /api/health`.

## Демонстрационные пользователи

В MVP пароль совпадает с логином: `officer`, `registrar`, `zone`, `engineer`, `analyst`, `admin`. Это сделано только для учебной демонстрации и должно быть заменено OAuth 2.0 перед промышленным использованием.

## Запуск на se.ifmo.ru

На сервере пароль PostgreSQL считывается скриптом запуска из уже настроенного `~/.pgpass` и не сохраняется в репозитории.

```bash
cd ~/ep-island
export JAVA_TOOL_OPTIONS='-Xms32m -Xmx256m'
mvn -DskipTests package
chmod +x scripts/*.sh
./scripts/run-server.sh
```

Остановка выполняется командой `./scripts/stop-server.sh`. Лог приложения: `~/ep-island/ep-island.log`.

Входящие HTTP-подключения к пользовательским портам Helios фильтруются. Для демонстрации откройте SSH-туннель на рабочем компьютере:

```bash
ssh -p 2222 -L 25074:127.0.0.1:25074 s507491@se.ifmo.ru
```

Пока SSH-сессия открыта, интерфейс доступен по адресу `http://127.0.0.1:25074`.

Сквозной приёмочный тест UC-01–UC-05 запускается на сервере так:

```bash
cd ~/ep-island
CURL=/usr/local/bin/curl ./scripts/smoke-test.sh
```

## Ограничения прототипа

- внешний реестр и бухгалтерская система имитируются;
- OAuth 2.0 заменён демонстрационной сессией с ролевыми ограничениями;
- push-уведомление представлено созданием задания инженеру в интерфейсе;
- прогнозирование на 1–3 месяца не входит в сквозные UC-01–UC-05 версии MVP.
